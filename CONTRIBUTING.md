# Contributing to Sagavar 🤝

First of all: **thank you for being here!** Sagavar is a learning project — contributions from beginners are especially welcome. Questions, half-finished ideas and "I don't know if this is right, but…" pull requests are all fine. 💜

## 🐛 Reporting a bug

1. Go to the [Issues](https://github.com/danilo-labs/Sagavar/issues) section.
2. Click **New issue** and choose the **Bug report** template.
3. Fill in as much as you can — a bug we can reproduce is a bug we can fix.

Before opening a new one, please search existing issues: maybe it's already known.

## 💡 Proposing a new feature

1. Open an issue and choose the **Feature request** template.
2. Tell us your idea, why it would be useful, and how you imagine it working.
3. Wait for a short discussion before writing lots of code — the [Roadmap](README.md#-roadmap) in the README shows where the project is heading.

## 🔧 Submitting a Pull Request

Never done one before? It looks harder than it is:

1. **Fork** this repository (button at the top right).
2. **Clone** your fork and create a branch:
   ```bash
   git checkout -b my-feature
   ```
3. **Make your changes** and commit them with a short, clear message.
4. **Push** the branch to your fork:
   ```bash
   git push origin my-feature
   ```
5. Open a **Pull Request** on GitHub from your branch to `main`, filling in the PR template.

### Good to know

- The whole UI is a single `sagavar.html` file — you can open it in a browser to try your changes (a backend like KoboldCpp or Ollama is only needed for actual answers).
- Keep PRs small: one feature or one fix per PR is perfect.
- Write commit messages in English if you can (but we won't reject a good fix for a commit message 🙂).

## 🌍 Multilingual help

The README is in English, Russian and Chinese. If you can improve any of the translations — including these docs — that's a contribution too!
